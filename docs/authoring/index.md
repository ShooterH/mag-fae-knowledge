# 增改模板

知识库的价值不在“写得多”，而在**下一次遇到同类问题时能迅速找到、判断并复用**。新增内容遵循以下流程。

## 新增一篇文章

1. 复制[文章模板](article.md)到 `docs/subjects/` 或 `docs/fae/`，使用小写英文文件名和连字符。
2. 先写“适用范围、结论、不适用项”，再补原理和应用。
3. 为每个关键事实分配来源 ID；先在[来源库](../sources/index.md)登记，再在正文引用。
4. 把状态设为 `草稿`。对照原始资料复核后改为 `已复核`；有实测再补实测条件和日期。
5. 在所在目录的 `.pages` 中安排导航，或让 `awesome-pages` 自动发现。
6. 本地运行 `mkdocs build --strict`，再检查手机宽度下的表格和公式。

## 新增一条来源

复制[来源模板](source.md)，按以下优先级选择：

1. 国际/国家计量机构、标准组织、政府或大学公开课程。
2. 目标器件/材料原厂的现行数据手册、应用笔记、官方软件文档。
3. 正式出版的教材或同行评审论文。
4. 工程推导和内部实测，必须明确标记，不能伪装成外部权威。

同一来源更新版本时，不覆盖旧记录；新增版本并在正文说明结论是否变化。

## 更新流程图

流程图在页面中显示为静态 SVG，避免手机端加载数 MB 的 Mermaid 脚本：

- 源文件：`docs/assets/diagrams/src/*.mmd`
- 页面图片：`docs/assets/diagrams/*.svg`
- 修改时，将 `.mmd` 导入 [Mermaid Live](https://mermaid.live/)，导出 SVG，覆盖同名文件；不要直接手改压缩后的 SVG 路径。

## 记录一次客户支持

先复制[案例模板](case.md)，默认放在**私有工作区**。只有完成脱敏和审批后才进入公开 `cases/`。无法公开时，可以只把可泛化的机理写进学科文章，不保留客户细节。

## 内容质量红线

- 不把典型值写成保证值。
- 不把某型号的测试条件省略成“行业通用”。
- 不引用无法访问或无法确认题名的资料。
- 不把仿真收敛当作模型已验证。
- 不用校准掩盖随机噪声、温漂或机械松动。
- 不公开受版权保护的整书、整页扫描或大段原文。
